# ADR-010：严格可达分已登记与假设，业务命题写到 owner 决策层

```text
日期: 2026-11-12
状态: 提议
关联 run: runs/2026-11-12-JOB-0-run5.md

决策:
1. 「严格可达」只能统计已在 2026-11-12 补登表中登记的字段（含子字段），
   且导出元数据（账号、时间）已写入证据包封面。依赖未登记子字段、未填的
   账号表、或尚未写入 ADR 的新约定的，标「假设可达」或「条件闭合」，
   单独计数，不得并入严格可达。报告必须写「已登记 X 条 + 假设 Y 条」，
   不得只写一个总数。
2. 业务命题必须写成 owner 要决定的业务结果，不能写成控制动作。
   每条业务命题至少映射一个控制命题；控制命题闭合不等于业务命题闭合。
   业务命题与控制命题分表登记。

当时的约束:
run5 的 14 条「严格可达」实际是 8 条无假设 + 5 条依赖 A-1 子字段
（P2 / P3 / P6 / P17 / P21）+ 1 条依赖账号登记（P23）。A-1 明确不是
已登记能力（G-R5-4），但 §4.4 和 Q3 仍写「14 条严格可达 / 14 条闭合」；
运行记录第 41 行还写「14 条严格可达全部建立在补登表上」。
C-2 的业务命题写成 P9「行数与校验和一致」，但 owner 要决定的是
「迁移正确且可回滚」；P10 只出现在「不声称」里。
C-6 的业务命题写成 P20「24h 内补单」，这是控制，不是业务结果；
真正的业务命题是「紧急修复的风险被登记、复盘、不扩大」。
P17 的 copy-ok 和 P21 的 postmortem 是新约定，但没有写入 ADR；
它们的闭合依赖团队采纳一个还没记录的行为规则。

考虑过的其他选项:
- 保留「14 条严格可达」，只在脚注写 A-1：不采纳。这就是 run4 的
  「9 条闭合」同一类高估；脚注不会进入 headline。
- 把所有 A-1 契约直接标「待核」：不采纳。A-1 与「字段缺失」不同，
  它是有明确假设的可用证据；直接降待核会丢掉「假设内容」这个信息。
- 增加「部分闭合」状态：不采纳。四态 + 已登记/假设二分已经够用；
  再加一态会变成分级表演。
- 把业务命题直接等同于控制命题：不采纳。控制闭合只能证明证据链，
  不能证明 owner 要的业务结果；C-2 / C-6 已经暴露这个错误。

依据:
ADR-005：严格可达要求字段已登记、导出可追溯。
ADR-006：证据字段必须能直接支持命题。
ADR-007：业务命题与可证命题分开；不得靠收窄命题消灭缺口。
ADR-008：证明闭合必须逐项覆盖命题的合取项。
run5 §4.2 的表把 5 条标成「严格可达（A-1）」、1 条标成「依赖账号登记」；
run5 §4.4 / Q3 仍汇总为「14 条严格可达」；
run5 运行记录第 41 行「14 条严格可达全部建立在补登表上」与 G-R5-4 冲突；
run5 §4.3 的 C-2 用 P9、C-6 用 P20 作为业务命题。
（本条依据是 run5 文本的内部不一致与任务契约，不是 L2 设计主张；
  cases/ 为空，故标「提议」。）

预期效果与验证方式:
下一轮报告里：
1. 严格可达按「已登记 X + 假设 Y」报告；假设可达逐条列出假设内容；
2. 业务命题表只写 owner 要决定的业务结果，控制命题另表；
3. C-2 的业务命题是「迁移正确且可回滚」，P9 / P10 是它的控制；
4. C-6 的业务命题是「紧急修复的风险被登记、复盘、不扩大」，P20 / P21 是控制；
5. P17 / P21 依赖未入 ADR 的约定，标「条件闭合」，不计入已登记可达。
验证方式：抽查 3 条假设可达，确认假设内容可被验收方接受或拒绝；
抽查 2 条业务命题，确认它们不是控制动作的同义改写。

推翻条件:
- 如果代码仓库 / 工单 / CI 的实际 API schema 明确登记了 A-1 子字段
  （author、created_at、path、body）和 PR author，则 A-1 契约转为已登记可达。
- 如果账号表在生效前填好，P23 转为已登记可达。
- 如果团队把 copy-ok / postmortem 写入 ADR 并采纳，P17 / P21 转为已登记可达。
- 如果业务命题无法在不写控制动作的情况下表达（例如纯合规场景），
  允许把控制动作作为业务命题的代理，但必须标明代理关系。

已知局限:
- 「假设可达」不是质量判断；它只说明证据依赖一个未登记的前提。
- 业务命题的层级是判断，不是机械规则；owner 可能把控制动作当成业务结果。
- 本条会增加报告长度；对低风险变更可以只报控制，但不得把控制闭合
  写成业务闭合。
- 本条不解决 A-1 子字段本身是否真实存在；那要等 G-R5-4 补登或实际 schema 核对。
```
