# ADR-005：「可达」必须同时具备导出人与字段，缺一标「待核」

```text
日期: 2026-11-12
状态: 提议
关联 run: runs/2026-11-12-JOB-0-run3.md

决策:
证明契约的「可达」按四个条件判定：
  ① 系统在 JOB-0 证据能力清单内；
  ② 字段名已登记；
  ③ 导出人可指名（或判定人本人有导出权限）；
  ④ 导出带时间戳与操作者。
四项齐全 = 严格可达；①②成立但③或④缺 = 待核；
系统或字段在清单内无来源 = 缺失；系统存在但能力未登记 = 未成立。
比例必须按「严格可达 / 待核 / 缺失 / 未成立」四列报告，
不得把待核并入可达，也不得只报一个合并后的比例。

当时的约束:
JOB-0 的 2026-11-11 表只登记三个系统的「可达」状态，未写导出人、粒度、
字段名；2026-11-12 表为工单、CI、发布平台、代码仓库补了这三项。
本轮 13 条契约中：8 条严格可达、3 条待核（P-3 / P-7 / P-8）、
2 条缺失（P-6 / P-11）。按 JOB-0 状态列合计是 11/13，
但 11 中只有 8 条能闭合到「谁导出、什么字段、谁判定」。

考虑过的其他选项:
- 沿用三态，把 3 条待核并入「可达」：不采纳。会让 11/13 看起来像
  11 条都已闭合，掩盖旧三系统的登记缺口，正是 ADR-003 要防的
  「用措辞让条目看起来成立」。
- 把 3 条待核直接降为「未成立」：不采纳。JOB-0 已登记它们「可达」，
  降为未成立等于否认场景契约；问题在元数据不全，不在能力不存在。
- 等场景 owner 补登三个旧系统后再重跑，不在本轮报告：不采纳。
  会丢掉「当前到底有几条真正闭合」这一可复核事实，也让下一轮的
  改进无法归因。
- 设「部分可达」第五态：不采纳。四态已经够用；再加一态会让报告
  更像分级表演，而不是可执行的核对。

依据:
JOB-0.md 使用边界 1：导出必须带时间戳与操作者 / 服务账号；没有操作者的
  导出不能作为判定证据——无法核查判定人是否独立于产出者。
JOB-0.md 登记规则：未列出的能力视为不可达；需要证据时要么换成表内可达的
  证据源，要么明确标「未成立」。
ADR-003：系统「存在」不等于「可作证据」；未登记能力的系统不得用于判定。
ADR-004：补登是场景契约修订，不是能力改善证据。
（注：上述均为任务契约或 ADR，不是带等级的 L2 设计主张；docs/ 主张仍未
  标等级（G-2），cases/ 为空。依据不足 L2，故本条只能标「提议」。）

预期效果与验证方式:
下一轮重跑的报告里，13 条契约分成四列，P-3 / P-7 / P-8 不再被计入
严格可达；读者能直接看到「8 条闭合、3 条待补元数据、2 条缺失」。
验证方式：
1. 新报告是否把待核单列，且没有只报一个 11/13；
2. 若场景 owner 补登三个旧系统，待核是否转为严格可达，
   比例是否从 8/13 变为 11/13，且差异能归因到登记表变化；
3. 新报告是否仍为每条严格可达写出导出人与判定人，而不是只写系统名。

推翻条件:
- 真实组织核对后发现判定人无需登记导出人即可独立取得证据，且导出
  自带操作者与时间戳 → 「待核」这一状态可取消，退回三态。
- 下一轮执行者仍把待核并入可达，且未附清单 → 说明四态只活在 ADR 里，
  应把四态写进 JOB-0 的验收标准，而不是继续靠 ADR 约束。
- JOB-0 的证据能力表被整体替换为「每条证据自带导出人与字段」的格式 →
  本条退化为一次性检查，可废弃。

已知局限:
- 本条只改报告口径，不创造证据。8/13 仍是给定能力下的严格上限；
  它不说明方案本身有效，只说明证据链闭合到哪一步。
- 低风险、可逆、无审计要求的变更可以简化，不必套四态；
  本条针对的是后果性变更的验收。
- 「导出人可指名」仍可能被写成角色而非具体人；下一轮需要核查
  授权包里是否真的有名字，而不是「系统管理员」四个字。
```

## 与 ADR-004 的关系

ADR-004 说补登后「可用条目应为 11/13」，并把 11/13 定为给定场景能力下的
上限。本条不推翻这个上限，只是把 11 拆成 **8 条严格可达 + 3 条待核**。
两者可以同时成立：

- 按 JOB-0 状态列：11/13 可达（ADR-004 的口径）；
- 按本条四条件：8/13 严格可达、3/13 待核、2/13 缺失。

若把两者混读成「11 条都已严格成立」，就是 ADR-004 自己写下的误用条件
（把补登当能力改善、把可达当已采集）。本条是对该误读的护栏。

## 为什么不标「已接受」

依据是 JOB-0 的任务契约与 ADR-003 / ADR-004，不是带等级的 L2 设计主张；
`docs/proof.md` 的 L1 / L2 关系仍有歧义（G-1），`docs/` 主张仍未标等级
（G-2），`cases/` 为空。标「已接受」等于用「这是口径必然」的措辞冒充
证据——正是 `docs/proof.md` 要防的事。等下一轮用四态报告跑通，
再考虑是否升为已接受。
