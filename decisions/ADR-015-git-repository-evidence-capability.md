# ADR-015：git 作为本仓库的登记级证据能力

```text
日期: 2026-11-13
状态: 已接受（2026-11-13，依据 CHANGE-4；见文末「状态变更记录」）
关联 run: runs/2026-11-13-CHANGE-3.md；无 case（cases/ 为空）

决策:
1. 在本仓库（ai-native-org/）登记 git 为一项证据能力，效力仅限本仓库。
   它不进入 JOB-0 的四系统补登表，不能用于证明 JOB-0 虚构场景的契约。
2. 证据能力登记如下：

   | 证据源 | 谁能导出 | 粒度 | 字段名 | 状态 |
   | --- | --- | --- | --- | --- |
   | git（本地仓库） | 任何能读工作区的人 / agent；提交身份由本地 git config 决定；owner 可读全部历史 | 按 commit / 按文件 / 按路径 / 按分支 / 按时间窗 | `commit_sha`; `parent_sha`; `tree_sha`; `author_name`; `author_email`; `author_date`; `committer_name`; `committer_email`; `commit_date`; `commit_message`; `changed_files`; `diff`; `diff_stat`; `blob_sha`; `branch`; `tag`; `status`; `log` | 可达（本仓库登记；ADR-015 状态：提议） |

3. 使用边界（与登记表同样有效）：
   a. `commit_sha` 只证明内容身份，不证明内容正确、测试通过或生产可用。
   b. `author_name` / `author_email` 来自本地配置，可被任意设置，不构成
      身份证明；独立性只能按「判定人 ≠ 产出者」判定（ADR-001 / ADR-011）。
   c. `git diff` 只证明文本改动，不证明语义等价；二进制文件要用
      `git hash-object` / `git show`，不得用 `diff` 冒充可读证据。
   d. 判定「只改了预期文件」必须同时记录变更前 / 后的 `git status --porcelain`；
      只看 `git diff` 不能排除未跟踪文件或改前已脏的工作区。
   e. 本地 `git log` 可被 `commit --amend`、`rebase`、force push 改写，
      不是防篡改审计；需要防篡改时必须另接远端保护或签名提交，当前未登记。
   f. `author_date` / `commit_date` 是本地时钟值，可被改写，不是可信时间戳；
      使用时要写明取的是哪一个，并承认它只证明「提交记录声称的时间」。
   g. `commit_message` 是自由文本，不得按固定格式解析成结构化证明字段
      （ADR-012 d）。
   h. 文件路径集合以 `git ls-files` / `git diff --name-only` 为准，不另维护
      一份手工路径清单（ADR-012 a / b）。
   i. git 不提供 `export_actor` / `exported_at`；EPC 仍按 ADR-011 的登记层
      口径使用，不得宣称系统审计。
4. 字段语义：
   - `diff` = 文本补丁；`diff_stat` = 每文件增删行数；两者都不能证明语义等价。
   - `changed_files` = 该 commit 涉及的路径，不等于工作区全部文件。
   - `author_date` = 作者声称的写作时间；`commit_date` = 提交记录时间。
     判定「变更时点」时优先用 `commit_date`，并写明它不可信。
5. 使用条件（缺一不得标「已登记可达」）：
   a. 变更前有一个干净基线 commit，并记录 `base_commit`；
   b. 变更后有一个 `change_commit`，且 `git status --porcelain` 为空；
   c. EPC 封面包含采集人、导出时间、对象 ID（`commit_sha` + 路径）、
      文件 SHA-256 / `blob_sha`、判定人；
   d. 判定句只使用 `git diff base..change -- <paths>` 与
      `git status --porcelain` 的结果，不引用命题之外的字段；
   e. 判定人不是该变更的产出者（ADR-001）。
6. 本 ADR 不证明：提交者身份、独立评审、测试结果、运行时状态、生产状态、
   JOB-0 场景能力、远端备份、防篡改。它只把「本仓库的文本改动」变成
   可逐行核对的登记级证据。
7. 对变更卡的影响：
   - 以后本仓库的变更卡可以引用本 ADR 的字段，把「只改了预期行」这类
     命题标为已登记可达；前提是第 5 条五项齐全。
   - CHANGE-1 的 A-1 与 P2 / P3 不会因本 ADR 自动转已登记；它改前没有
     副本，缺口仍是缺口。
   - CHANGE-2 的证据可在 owner 明确同意后按本 ADR 重判；本 ADR 不自动
     升级任何历史卡。

当时的约束:
- 本仓库是文档项目，没有工单、CI、发布平台；此前没有版本控制，CHANGE-1
  因此只能记哈希、无法证明「只改了一行」。
- 2026-11-13 已初始化本地 git（main 分支，初始 commit eebaf2a），并加入
  `.gitattributes` 固定 LF，避免 CRLF 把单行改动显示成整文件 diff。
- 本仓库只有 owner 与 agent；没有第二方独立判定；git 的 author 字段不能
  补这个缺口。
- ADR 状态仍为「提议」；cases/ 为空；无 L3。本 ADR 是仓库级证据登记，
  不是设计结论。

考虑过的其他选项:
- 直接用 GitHub 作为证据源：不采纳为第一步。远端能提供备份、PR 评论和
  分支保护，但也会引入公开 / 私有、隐私与账号归属问题；本地 git 是
  最小可用集。
- 把 git 当成系统审计：不采纳。author / commit_date 都可由本地配置与
  时钟改写，不能证明「谁在何时执行了导出」。
- 把登记写进 JOB-0 的四系统表：不采纳。JOB-0 是虚构场景契约，git 是
  本仓库的工具；混在一起会让下一轮执行者误以为场景多了第五个系统。
- 只写在 templates/change-card.md 里：不采纳。模板是登记面，不是权威；
  ADR-012 要求输入集合登记在 JOB-0 或 decisions/。
- 只用 `git diff` 不记 `git status`：不采纳。未跟踪文件与改前脏工作区
  会漏掉，无法证明「只改了预期文件」。
- 用 `author_date` 当可信时间戳：不采纳。本地时钟可改，且与
  `commit_date` 可能不同；必须写明取哪个，并承认不可信。

依据:
ADR-002：第二方是证据产出方，不是共同 owner；git 的 author 不能替代它。
ADR-003：系统存在不等于可作证据；未登记的能力不得假定可达。
ADR-011：EPC 是登记面，不是导出审计面；git 没有 export_actor / exported_at。
ADR-012：判定规则可自定，但输入集合必须登记；本 ADR 登记路径、清单、
  命名、解析与字段语义五类中的相关项。
ADR-014：D-2 判断资产变更新增 ADR / 模板时走全卡；本 ADR 是 D-2。
2026-11-13 的 git 事实：eebaf2a（初始提交）、a8850e2（CHANGE-2 修复）、
  d2b2c4b（CHANGE-2 记录）；`git diff` 可逐行核对。
以上依据是任务契约、ADR 与本地 git 事实，不是 cases/ 的 L2 主张；
cases/ 为空，因此本条标「提议」。

预期效果与验证方式:
- 下一张本仓库变更卡可以写：`base_commit`、`change_commit`、
  `git diff base..change -- <paths>`、变更前后 `git status --porcelain`，
  并把「只改了预期行」标为已登记可达；不再出现 CHANGE-1 的 P2 / P3 缺口。
- 验证方式（下一张卡逐条检查）：
  1. 卡是否引用 ADR-015 并写明 ADR 仍为「提议」；
  2. 是否同时有 base_commit、change_commit、变更前后 status；
  3. diff 是否只覆盖命题列出的路径；
  4. 判定人是否不是产出者；
  5. 是否没有把 commit author 当成身份证明或系统审计。
- 可观察行为：同类变更的证据栏不再写「无版本控制」；要么按本 ADR 的
  五项条件标已登记，要么明确说明缺哪一项、只能标假设。

推翻条件:
- 仓库被重新初始化、历史被改写或基线 commit 丢失 → 依赖该基线的卡失效，
  本 ADR 对该段历史不再适用。
- 出现一次「卡标已登记可达，但没有 base_commit / status / EPC 封面」的
  实例 → 说明第 5 条没有被执行，应收紧为检查表或暂停使用。
- 提交身份被共享、代签或被当成独立评审 → 第 3b 条被违反，git 只能用于
  内容比对，不能用于任何独立性主张。
- 接入远端并启用分支保护 / 签名提交 → 更新本 ADR，增加远端审计字段；
  不得假定远端自动继承本 ADR 的「已达」状态。
- 仓库不再使用 git → 本 ADR 失效，相关卡退回「缺失」或「假设」。

已知局限:
- 本地 git 不是防篡改审计；没有远端保护、签名提交或第三方时间戳。
- author / committer 字段不证明现实身份；单人仓库没有第二方独立判定。
- `git diff` 只覆盖文本；二进制、生成物、外部系统状态不在本 ADR 范围内。
- 无真实案例，L1 为空，无 L3；本 ADR 只在本仓库有效。
- 它会让「已登记可达」的数量上升，但上升来自证据能力登记，不是方案变好；
  报告不得把两者混读。
```
