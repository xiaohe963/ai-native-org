# ADR-013：结构化 PR 评论约定（release-go / copy-ok / postmortem / migration-review）

```text
日期: 2026-11-13
状态: 提议
关联 run: runs/2026-11-12-JOB-0-run5.md、runs/2026-11-13-JOB-0-run9.md；
         无 case（cases/ 为空）

决策:
1. 所有需要「非产出人复核 / 批准」且以 PR 为载体的变更，统一用
   review_threads 中的结构化评论留痕，不再分散成多条约定。
2. 四类评论格式：
   - `release-go ticket=<id> scope=<摘要>`：负责人批准发布（沿用 ADR-009）；
   - `copy-ok ticket=<id>`：设计确认客户可见文案；
   - `postmortem ticket=<id>`：紧急修复复盘，正文含影响范围、根因、后续动作三项；
   - `migration-review ticket=<id>`：非迁移执行人的迁移脚本复核，正文含
     不可逆点与回滚路径。
3. 评论必须含 author、created_at、body 三个子字段。补登表只登记了
   `comments` / `review_threads` 对象名，未逐项登记子字段（G-R5-4 未执行），
   因此依赖评论子字段的契约仍标「假设可达」，本 ADR 不改变这一点。
4. 评论格式是团队约定，不是系统能力；它不替代系统审批字段，也不证明
   评论不可篡改或作者身份不可借用。系统级导出归属仍按 ADR-011 的登记层口径。

当时的约束:
- ADR-009 只对 `release-go` 做判断；`copy-ok` / `postmortem` 在 run5 已出现，
  但一直没入 ADR，只能标条件闭合。
- run9 的 R9-P7 使用了 `migration-review` 评论，但假设列表 A-4 只含
  `copy-ok` / `postmortem`，漏了这一类；说明分散约定会被漏掉。
- 工单没有 `release_go_by` / `release_go_at`（G-14 未执行）；权限系统与
  发布平台没有审批字段；PR 评论是清单内唯一可用的留痕载体。
- ADR-009 状态仍是「提议」；本 ADR 合并四类约定，不把它升为「已接受」。

考虑过的其他选项:
- 只扩展 ADR-009：不采纳。ADR-009 的命题是「批准留痕绑定被批准对象」，
  只适用于批准；copy-ok / postmortem / migration-review 是复核与复盘，
  不是批准，混进去会让「批准」和「复核」失去区分。
- 每类评论各立一条 ADR：不采纳。四条格式同构，分开会增加维护成本，
  而且 run9 已经证明分散会漏（migration-review 没进假设）。
- 用系统审批字段：不采纳。工单、权限系统、发布平台都没有可导出的
  批准人 / 批准时间字段；G-14 执行前没有替代载体。
- 不写 ADR，继续靠提示词：不采纳。run5 / run9 已两次出现「约定未入 ADR
  → 只能条件闭合」，不固化会重演。

依据:
ADR-009：release-go 评论绑定被批准对象；工单布尔值只作镜像。
ADR-010：依赖未写入 ADR 的新约定，只能标假设可达。
ADR-012：判定规则可自定，但输入集合必须登记；评论格式属于输入集合。
JOB-0 使用边界 5：非产出人复核必须在 comments / review_threads 里留痕。
run5 的 copy-ok / postmortem；run9 的 migration-review 及其假设漏项。
以上依据是任务契约与运行文本，不是 cases/ 的 L2 主张；因此本条标「提议」。

预期效果与验证方式:
- 下一轮 P3 / P7 / P14 / P16 不再因「评论约定未入 ADR」而降级；
  它们仍因 review_threads 子字段未登记而标假设可达（A-1）。
- 验证：抽查四条依赖评论的契约，逐条问「这个评论格式写在哪」；
  四类都能指到本 ADR 即通过；任一仍写「未入 ADR」，说明本 ADR 没被读到
  或没写清。
- 可观察行为：每个 PR 载体变更在合并/发布前有对应格式的评论；
  评论 author 与 created_at 可导出。

推翻条件:
- 团队不再以 PR 为载体发布（直接推送、纯配置发布、非 PR 迁移）。
- 评论可被无痕编辑 / 删除，author / created_at 不可信。
- 负责人账号不唯一或可共享，无法把评论绑定到具体决策人。
- 合规要求批准必须落在工单 / 审批系统，PR 评论不被接受。
- 评论格式漂移，判定人无法按格式核对。

已知局限:
- 子字段未登记，四条依赖评论的契约仍只能标假设可达；本 ADR 不解决 G-R5-4。
- 不证明评论内容正确，只证明留痕存在且格式匹配。
- 不证明评论不可篡改、作者身份不可借用。
- 不替代法定双签、法务审查或合规审批。
- 非 PR 载体的数据迁移与权限变更仍无留痕载体。
- 无真实案例，L1 为空；不能证明该约定在真实组织中的执行率。
```
