# ADR-001：执行者是 agent 时，判定人必须是人

```text
日期: 2026-11-11
状态: 提议
关联 run: runs/2026-11-11-JOB-0.md

决策:
当某次交付的执行者是 coding agent 时，其证明契约的判定人必须是人，
不能是同一次运行内的另一个 agent，也不能是该 agent 的自评。

当时的约束:
60 人公司 / 8 人团队 / 无专职安全与合规岗 / 两周时间窗。
若组织规模、监管要求或可观测能力变化，本结论可能不成立。

考虑过的其他选项:
- 由另一个 agent 独立判定：不采纳。同一次运行共享上下文与失败模式，
  不构成独立证据，只是把同一判断重述一遍。
- 由产出 agent 自评 + 人工抽查：不采纳。抽查覆盖率无分母定义，
  且 docs/proof.md 明确禁止把 agent 自述当证据。
- 由 CI 结果自动判定：不采纳。CI 绿只证明那条断言成立，
  不能覆盖「用户或运维主张」这一层。

依据:
docs/domain-model.md「证明契约」不变量：判定人不能是产出者自己。
docs/proof.md：禁止当作证据的清单包含 agent 自述。
（注：docs/proof.md 未定义 agent 场景下「产出者」的边界，本 ADR 是对该
  缺口的解释，不是对已有规则的复述；等级歧义见 JOB-0 baseline。）

预期效果与验证方式:
JOB-0 交付物第 4 节的六个判定人全部是人且独立于产出者。
验证方式：在真实组织跑一轮，核查每条证据是否由所列判定人实际采集，
而不是由执行者代填。

推翻条件:
出现可核查的、跨多次运行的「agent 判定 vs 人工判定」一致性数据，
且覆盖至少一类失败案例，使得 agent 判定的独立性可被证明；
或监管要求明确允许自动判定。

已知局限:
cases/ 为空，无任何真实案例支撑；无 L3 证据。本条为解释性提议，
不得据此推广到其他团队或作为规则引用。
```

## 为什么标「提议」而不是「已接受」

`decisions/` 只允许引用 L2 及以上主张，而 `docs/proof.md` 的等级定义
存在歧义（L2 是否必须包含 L1 的真实案例），本次又没有任何真实案例。
在规则歧义未裁决、案例库为空的情况下标「已接受」，等于用措辞
冒充依据——正是 `docs/proof.md` 要防的事。
