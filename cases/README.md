# 案例库

只放**真实发生过**的事实，不下结论。论证放 `docs/`，一个案例可以被多条主张引用。

## 案例卡片模板

```text
标题:
时间:
组织规模与类型:
当时的具体约束:
发生了什么（可核查的事实）:
来源（链接 / 出处 / 可访问性）:
后来怎样（如有）:
哪些主张会受它影响（只列编号，不写判断）:
采集日期:
```

## 规则

- 必须带时间、规模、当时约束、来源。缺一项标 `_incomplete-` 前缀。
- 反面案例和失败案例优先级高于成功案例。
- 不要为了支撑某条主张而裁剪事实；冲突的事实原样保留。
- 不能公开的内部信息：只写可公开的抽象，注明访问级别，不放原文。
- 外部组织的当前运行状态留在它自己的权威系统里，本库不保存副本。

## 首批建议采集方向

- 决策权与能力被混用导致的事故（发布、数据、权限三类各一）
- 一次"全员透明"反而拖慢决策的实例
- 一次复盘真正让同类问题不再复发的实例，以及一次没做到的
