# 审查一份已有设计方案

用于别人给来的、或历史沉淀的组织设计方案。只读审查，不改原文。

## 六问（逐条给证据，不要给印象）

1. 后果性变更清单在不在？每类能不能指名决策权 owner？
2. 决策权与执行能力是否被分开登记？有没有"能调接口"被写成"有权变更"？
3. 每个授权包有没有回滚路径和撤销人？
4. 验收证据是否能在真实环境采集？判定人是不是产出者本人？
5. 每条关键事实是不是只有一个权威来源？
6. 有没有写明推翻条件？是不是具体可观察信号？

## 输出格式

```text
结论: 可接受 / 有条件接受 / 不接受
通过项（逐条附证据位置）:
缺口（按最早 owner 排序，不按严重程度）:
最小修复建议（每条注明会引入什么维护成本）:
本次审查未覆盖的范围:
```

## 禁止

- 用"不够清晰""缺乏整体性"这类无法证伪的评语
- 因为方案不符合本仓库术语就判不合格（本地契约优先）
- 在审查里顺手重写方案（另开任务）
