# 决策权与授权

## 主张

> 能力越大不等于授权越大。把两者合并，是 AI 原生组织最常见的失效模式：
> 一个能调用生产系统的 agent 被默认当成"可以做生产变更"，出事后才发现
> 没有人拥有过那次决策。

**可证伪条件**：如果存在一类后果性变更，其决策权无法指名到具体的人，
或授权包缺少回滚路径，则本主张在该场景下未被满足——记录到 `cases/`，
不要修掉这个反例来"让主张成立"。

## 设计规则

1. 先列**后果性变更清单**，再分配决策权。不要先画组织图。
   后果性 = 不可轻易回滚 / 影响外部用户 / 涉及资金、数据、权限、发布。
2. 可逆环境（分支、沙箱、草稿、预发）默认宽授权；后果性操作默认窄授权。
   宽授权不是放任，是把审批成本从每次操作移到边界上。
3. 授权包必须六项齐全：范围、时限、额度、审计、撤销人、回滚路径。
   缺一项视为未授权。
4. 能力变更（接入新工具、模型升级、开通新数据）触发**授权复审**，
   但不自动扩大授权。
5. 一个 agent 可以提出变更、准备证据、执行已批准的动作，
   但不拥有批准权，除非场景显式把该决策权指派给人以外的实体并写明问责人。

## 授权包模板

```text
变更类别:
授权范围:
有效期 / 触发失效条件:
额度或频次上限:
审计记录位置:
撤销人:
回滚路径与验证方式:
决策权 owner（可指名的人）:
执行者（人 / agent）:
```
